## 一句话概括

ARIADNE 提出一种以目标为导向的状态搜索框架，仅凭终端攻击请求即可自动重建有状态 Web 攻击的前置请求序列，为多步攻击的根因分析与复现提供自动化手段。

## 问题与动机

现代 Web 应用普遍具有状态性，利用关键漏洞往往需要一系列请求预先构造后端状态，形成多步有状态攻击。实践中 IDS/SIEM 只在携带异常行为的终端请求到达时告警，而前置的状态设置请求（如修改模板、更新配置）看起来符合合法 API 模式，被淹没在海量历史流量日志中，导致安全人员无法在沙箱中重放终端请求、难以进行根因分析、补丁验证与威胁狩猎。现有工具存在根本缺陷：面向 RESTful API 的序列生成模糊测试（如 MINER、VOAPI、NAUTILUS）是"目标盲"且依赖理想化 REST 语义或手工标注；灰盒与定向模糊器（WITCHER、ATROPOS、PREDATOR、WDFUZZ）的目标是单一代码位置而非复杂应用状态，无法构造跨多请求的状态设置前缀；同时这些方法对后端状态视而不见，不会从数据库中溯源已被攻击写入的参数值。以 CMS Made Simple 的 CVE-2021-26120 RCE 为例：攻击者先用 POST 将恶意 SSTI 载荷写入数据库，随后看似正常的首页 GET 请求才渲染被污染模板触发 RCE，而单独重放该 GET 请求必然失败。

## 方法

ARIADNE 将攻击重建形式化为有引导的状态空间搜索问题（灰盒范式：无需源码，只利用 syscall、数据库查询日志等执行反馈），由离线引导生成与在线目标导向模糊引擎两阶段构成。离线阶段构建三类引导模型：一是通过对终端攻击请求做动态分析（syscall 隔离与文件/数据库读依赖提取），构造刻画其全部后端数据依赖的目标状态画像，并经可插拔适配层统一为"表+行"表示（文件映射为 filename/content 概念表）；二是由正常流量数据驱动构建 API 依赖图（ADG），融合直接数据流（响应字段与请求参数值的 Jaccard 相似度）与经存储介导的间接状态流（写/读实体交集），即 W(u,v)=αPflow+(1−α)Pstate；三是基于 Jaccard 相似度学习参数-数据源关联模型。在线模糊引擎反复变异种子序列：API 选择采用多启发式打分 Score=Htrans^r1·Hgoal^r2·Happ^r3，其中 Hgoal 通过在反向 ADG 上做多源 Dijkstra（负对数权重）求到达目标 API 的最优路径概率，Happ 为参数可满足性可行性过滤；参数填充采用"状态驱动参数溯源"，依局部语料/目标画像语料/初始语料三层语料库及轮盘赌加权（ωlocal>ωtarget>ωinitial）回填值。每条候选序列由状态引导评估模块打分：状态距离定义为当前状态实体与目标实体间二部图最小权完美匹配代价（同表实体的属性距离求和，跨类型实体计固定惩罚 Cmismatch，默认 2），再与代码覆盖收益、响应值域收益加权合成，由模拟退火调度器更新种子池。原型用 9000 余行 Python 实现，采用预热 Docker 容器池隔离执行、符号引用机制处理会话 ID/CSRF 令牌等动态值，并配有自动攻击验证 oracle。

## 实验与结果

基准含 15 个真实世界有状态漏洞（来自 13 个广泛使用的开源应用），其中 10 个取自 Vulhub 筛选、2 个新近 2025 年 CVE（Kanboard CVE-2025-46825、Admidio CVE-2025-62617）、3 个取自 MINER/VOAPI 先前工作中链长≥5 步的复杂场景；每项实验重复 10 次取均值，硬件为 AMD Ryzen 9 7950X 与 32GB 内存。ARIADNE 成功率 100%，全部 15 条攻击链均在 20 分钟内重建完成（含一条 8 步链）；在 15 例中有 5 例找到比公开 PoC 更短的攻击路径（如将 GitLab 的 6 步 UI 流程压缩为直接 2 步 API 攻击）。基线对比中，即使被"增强"预先注入全部必要攻击载荷，MINER 仅解出两个最简 2 步攻击，PREDATOR 在两个适用多步场景上均失败，两者都无法重建任何 ≥3 步攻击；而 ARIADNE 未获该优势仍全部成功。消融实验（代表性子集 CVE-2016-9086 任意文件读取、CVE-2023-5002 RCE、CVE-2016-3088 任意文件上传）显示：去掉状态距离反馈使 TTV 恶化 3.2x–14.3x；去掉启发式 API 选择慢 3.8x–6.4x；去掉状态驱动参数溯源影响最重——在 3 个基准中的 2 个上超时，且 CVE-2016-9086 上慢逾 123x（6183.5s 对 50.4s）。YApi 未授权 RCE 案例研究（公开 PoC 需 8 步）中，ARIADNE 稳定找到更短路径（平均 6 步、最少 5 步），平均 234.4s 重建，代表性运行 160s 内完成 5 步路径，种子分数呈阶梯式上升（0.8→3.9→9.1→10.9）；关键一步中正确 API 在 18 个候选中排第 3（概率 8.3%），v_basepath 参数从目标画像溯源获得 40.4% 的最高选中概率。超参数敏感性实验表明框架稳健：融合因子 α 在 [0.2,0.8] 内最优，Cmismatch=2 时宏观平均 TTV 最低，各启发式权重扰动只引起分钟级 TTV 波动。

## 贡献与局限

贡献：首次将"重建状态设置型攻击前置序列"这一关键安全任务系统形式化为自动化、目标导向的状态搜索问题并提出完整框架 ARIADNE；设计以 syscall 分析构造目标状态画像、以最小权二部图匹配量化状态距离的精确导航体系；实现由数据驱动 API 依赖图、智能规划与后端状态参数溯源驱动的序列生成引擎，可高效还原攻击者原始信息流；在 15 个真实多步漏洞基准上全面评估，性能显著超越现有最先进基线，并开源工具（https://github.com/horis-dev/Ariadne）。局限：当前原型不原生解码不透明会话令牌/ Cookie，认证相关状态转换可能依赖启发式试错；引导模型依赖有代表性的正常流量，稀疏流量应用需额外构造基线；接入新应用有一次性的状态建模与流量采集成本（适配器平均约 58 行代码）；原型主要支持 SQL 数据库与本地文件系统，NoSQL、Redis、消息队列等需插件扩展；仅针对修改持久化后端状态的攻击，纯内存/无文件攻击（如内存 Webshell）不在当前范围内，未来可引入内存取证将内存实体纳入同一表式框架。
