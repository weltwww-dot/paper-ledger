## 一句话概括

IDORacle 在 ORM 或 SQL 数据访问边界重新绑定可信用户身份与具体对象授权关系，通过模板规划、SQL 重写、授权探测和可复用证明，在不改写大量遗留业务代码的情况下阻止越权读写。

## 问题与动机

IDOR/BOLA 的请求和 SQL 语法往往完全合法，真正缺失的是“当前主体是否有权访问这个对象”的语义约束。遗留应用中，身份信息通常停留在控制器或服务层，而下游 ORM、查询构造器或 SQL 只根据攻击者提交的对象 ID 执行操作，导致跨用户、跨租户的读取、修改、删除或状态变更。已有工作多集中于检测和修复，作者希望提供一个能部署到现有数据访问链路、同时保留合法操作的运行时防护机制。

## 方法

IDORacle 先把可信主体的 userId、role、tenantId 等信息绑定到请求上下文，再在 DAO/JDBC 或框架原生的数据访问边界拦截操作。Java 参考实现对参数化 SQL 归一化，结合 SQL 抽象语法树、操作类型、表列信息、策略元数据和策略版本生成模板计划；具体执行时可选择放行、注入所有权谓词、执行授权探测、阻断或审计。规则覆盖直接所有权、派生所有权、群组或租户成员关系、角色/状态转换、敏感列，以及公开表和管理员例外。Django、SQLAlchemy-compatible、xorm、Laravel Eloquent 和 CodeIgniter 适配器分别用 QuerySet、查询条件、仓储作用域或查询构造器实现同一主体—对象不变量；模板计划和授权证明可缓存以减少重复工作。

## 实验与结果

评估包含 8 个应用、21 条公开漏洞记录对应的 22 组配对授权用例，覆盖 Java 9 例、Python 6 例、Go 2 例和 PHP 5 例。每组都同时测试主体访问自己资源的合法轨迹，以及只替换对象标识或关系目标的越权轨迹。在灰盒测试中，未防护的每条攻击轨迹都产生越权数据库效果，攻击成功率为 100%；启用 IDORacle 后，所有越权读取、写入、删除、创建和状态变更均被阻止，残余攻击成功率和漏报率均为 0%，配对合法轨迹的误报率为 0%。Java 微基准中，单实例守卫处理的平均时间由无缓存时 0.17 ms 降至重复模板复用时 0.017 ms，约降低一个数量级；17 个端到端请求样本中，复用配置的平均受保护延迟均低于不复用配置。附录还对 19 个可表示为标量对象 ID 的用例分析了有限枚举攻击，已发现的越权 ID 在防护下仍无法产生数据库效果。

## 贡献与局限

论文把统一的主体—对象授权不变量落到 Java/MyBatis/JDBC 以及多种异构 ORM 和查询边界，并用配对基准同时证明越权阻断和合法行为保留，配套实现、案例与复现说明已公开。局限包括：防护依赖上游认证上下文和可观测的数据访问边界，不可观测的第三方服务、隐藏语义的存储过程或无法获得授权证据的动态业务状态可能绕过监控；跨语言适配器并不具备 Java 参考实现的全部模板规划和缓存优化；策略元数据仍需配置。实验样本是面向复现的受控集合，而非语言或框架安全性的总体排名，生产环境下的高并发、跨服务上下文一致性和策略漂移还需要进一步验证。
